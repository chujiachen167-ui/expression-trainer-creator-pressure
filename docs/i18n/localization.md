# Read Yourself 界面语言约定

## 已实现范围

- 产品界面支持 `zh-CN` 与 `en-US`。
- 用户的明确选择保存在当前设备；首次打开时按浏览器/系统语言选择中文或英文。
- 起始页、联系页以及 V1、V2、V3 的主标题、核心说明、主要操作与页面标题进入同一套语言目录。语言入口保留在起始页账户菜单与页脚，训练页沿用选择，不在顶栏重复出现。
- 中文是 founder 文案源。切换回中文时恢复页面加载后的中文内容，包括项目配置里已经保存的定制文案。
- 英文目前是可用的工作译文，不视为最终品牌文案；正式发布前仍需 founder 与母语审校。

## 必须保持分离的两个概念

1. **界面语言（Interface Locale）**：菜单、按钮、说明、页脚和页面标题使用的语言。
2. **诊断语言（Diagnostic Language）**：V1 语音识别和表达诊断要听懂的语言，例如“中英混合”或“English”。

改变界面语言不得自动改变诊断语言。用户可以使用英文界面训练中英混合表达，也可以使用中文界面训练纯英文表达。

## 文件与扩展方式

- `i18n.js`：语言选择、持久化、页面更新和事件通知。
- `locales/zh-CN.js`：中文目录与回退基准。
- `locales/en-US.js`：英文目录。
- 新增日语、韩语、俄语时，先补语言目录，再把语言代码加入 `SUPPORTED`；不要复制页面。

## 当前边界

- “人工验收调控板”是开发者工具，不属于普通用户产品界面的语言承诺，当前继续使用中文。
- 运行时生成的长篇诊断内容、观众台词和训练模板仍需下一轮逐项进入语言目录；本阶段先完成全站语言基础设施与用户主流程。
- 语言选择不使用国旗。语言代表的是书写和阅读偏好，不等于国家或地区。
