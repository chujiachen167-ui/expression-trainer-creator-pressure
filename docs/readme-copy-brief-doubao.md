# 工单：把 GitHub README 第一屏改成能让人读下去的中文介绍

把本文件**从头到尾**交给豆包执行。不要只贴「原文」一节。

你是中文文案改写，不是产品经理，不是翻译，不是技术文档作者。
读者是刚做自媒体的人。改完要像微信里把工具安利给朋友，不像官网，不像 README 说明书，不像国外模型写的书面中文。

只改**第一屏文案**（标题、一段话、适合谁、能练什么、怎么试、About 短描述）。
不要重写后面的安装细节、调控板、许可证。那些会另说。

---

## 1. 这页是干什么的

GitHub 仓库页 = 产品货架，不是开发备忘录。

路人点进来时仓库几乎没 star。他们不会因为标题或 star 留下来。他们要在大约 10 秒内产生两件事：

1. 这东西能覆盖我的需求。
2. 介绍得像那么一回事，不是一份作业说明。

读者需求（必须被第一屏对上，不要用内部模块名去对）：

- 一开摄像头就不会讲话 / 忘词 / 不敢看镜头
- 讲完不知道「嗯、那个、其实」说了多少
- 想在有人看着的压力下练，又不敢真去直播

不要写成「面向自媒体新手的镜头表达与可控压力训练桌面应用」。

## 2. 产品事实（不准改、不准发明）

对外产品名：**Read Yourself**  
技术名 / 仓库名：Expression Trainer · Creator Pressure（副标题可以出现，不要当主标题）

网站：https://read-yourself.com  
仓库：https://github.com/chujiachen167-ui/expression-trainer-creator-pressure

能做什么（用结果说，不要用 V1/V2/V3 当目录标题；需要对应功能时可以在括号里轻提）：

- 对着镜头讲一段话。可自己出题，或用账号介绍、知识口播、产品体验、观点、经历、方法这类现成题。
- 讲的时候有字幕。口头禅、笼统词、重复会被标出来。
- 可以加数字观众，模拟被看着的压力；同一题可以再讲一遍对比。
- 可以练广告植入、热点表态、直播回应、知识口播这类场面。
- 浏览器打开网站就能试（网页版用浏览器语音，能力比桌面版弱）。
- 完整离线转写和本机诊断在 **Windows 桌面版**。模型大约 1GB，只存在用户电脑，不随仓库分发。
- 摄像头默认只在当前页面预览。录像默认关。只有用户自己打开「同时录制」才会录。视频留在本机，不自动上传。
- 目前没有注册、云端账户、云同步。
- 这是能用的原型，不是课程平台，不是 MCN 后台，不帮人运营账号。

不准写：

- 虚构用户数、star、收入、媒体报道、保证变现、保证涨粉
- 保证「AI 会教你成为博主」
- 把网页版说成和桌面版一样强
- 把数字观众写成真人在看
- 把兴趣曲线写成精确科学（那是原型估算）

## 3. 结构要保留（抄的是结构，不是某个人的嗓门）

第一屏顺序固定，不要打乱成小红书种草长文：

1. 产品名
2. 一句结果（打开就能懂）
3. 能点的网站链接 + 一句隐私（镜头在你电脑上，默认不上传）
4. 图片占位（保留 markdown 图片行，不要删）
5. 适合谁
6. 能练什么（3～5 条，每条先结果后手段）
7. 怎么试（网页三步 + 桌面版命令原样保留）

可借鉴的手法（不要写成「以某某口吻」）：

- 第一屏就给结果和能点的东西，不要先讲架构
- 用「你」，少用「本产品」「用户」
- 用观众能感觉到的结果：「一说『那个』会被标出来」，不要「填充词指标模块」
- 代价要诚实：打开网页就能试；完整离线识别才需要装桌面版

明确不要学：直播吼叫、砸钱赠送、成功学、鸡汤、宝子/家人们/绝绝子。

## 5. 中文语义适配（这是你的主任务）

在**不改事实、不打乱结构**的前提下，把用词改成中国人会说的话。

要：

- 短句，能念出声
- 像口播新手互相推荐工具
- 保留「你」
- 专有名词可中英混用：Read Yourself、GitHub、Windows
- 「嗯、那个、其实」这类例子要留，这是读者能对上号的东西
- markdown 标题、链接、图片、代码块语法保持能直接贴进 README

不要：

- 面向 / 旨在 / 路径 / 赋能 / 闭环 / 可复用 / 可落地 / 一站式 / 全链路
- 场地 / 高压 / 基线能力 / 诊断核心 / Provider / 可审计
- 先写「它不是 A 而是 B」当开场（边界如果要写，最多一句，放在「适合谁」末尾，且要用口语）
- 小红书腔：宝子、家人们、绝绝子、封神、我直接哭死
- 成功学：改变命运、财务自由、你值得拥有
- 堆 emoji、徽章、星级
- 英文思维直译：make it easy to、empower you to、a repeatable practice path

「像人话」的验收：把改完的字读给一个不做开发的朋友听，他能听懂这是干嘛的，不会问「这是课程还是软件」。

## 8. 补充约束（容易漏，所以写在这）

- 仓库几乎没 star。禁止用「社区」「众多开发者」「广泛使用」。
- 作者是一个人在做原型。语气可以像个人工具，不要装成公司。
- 界面有中文/英文切换。第一屏不必展开 i18n，提一句即可，也可不提。
- 联系方式在网站页脚「联系与反馈」，第一屏不必放二维码。
- 调控板是开发用的，正式网站没有。第一屏不要提调控板。
- 封面图现在可能仍是起始页。文案不要写「上图是训练中的字幕」，除非图里真有字幕。写成中性：「打开后长这样」或干脆不描述图。
- 不要把 GitHub 介绍写成下载站长文。网页试玩是主路径，桌面版是进阶。
- 改完字数：第一屏正文（不含代码块）控制在大约 250～450 字。太短会空，太长没人滚。
- 标题用 `# Read Yourself`，不要用 `# Expression Trainer · Creator Pressure`。
- 不要加「Star 一下」求 star。
