## 一、问题定义

当前 Live2D 链路只证明模型能被读取并绘制出非透明像素，没有形成真正的动态角色：

1. `live2d-local-runtime.js` 读取 moc、贴图、表情和 Pose，但没有读取模型清单中的 `Motions`、`Physics`、`EyeBlink` 等动态资源。
2. `local-runtime/live2d-framework-bridge.js` 只在初始化或 `setExpression()` 时调用少量离散绘制，没有持续的 `requestAnimationFrame` 更新循环。
3. Hiyori 样例没有可供当前四态名称匹配的 Expressions，主要动态信息位于 Idle / TapBody motions；当前运行时忽略这些 motion，所以四态接口即使返回成功，画面也可能毫无变化。
4. 现有冒烟和单元测试只检查 canvas、可见像素、状态字段和接口返回值，没有证明相邻时间帧发生变化，也没有证明训练事件造成肉眼可见的角色反馈。

这不是美术微调问题，而是运行时能力缺失。不要通过放大贴图、增加 CSS 浮动或伪造随机表情来掩盖。

## 二、本单目标

把本地 Live2D 从“能够显示模型”提升为“能够持续存活并对训练事件作出可见反馈的数字观众”：

- 空闲时有自然、克制的待机动作；
- `confused / interest / drop` 由现有 V2 判断事件触发可见反应；
- 反应结束后回到 `listen` 待机；
- 动作不发声、不追问、不抢占麦克风，也不改变评分；
- 模型能力不足或运行失败时明确降级到已验收通过的 bloub。

## 三、必须交付

### 3.1 资产读取

- 解析 `.model3.json` 中的 `Motions`、`Physics`、`Pose` 和 `Groups`。
- 读取所需 `.motion3.json`、`.physics3.json` 等本地资源，并继续执行现有的相对路径、文件夹边界、格式和体积校验。
- 不上传模型，不允许远程 URL，不执行用户脚本。

### 3.2 连续帧运行

- 使用官方 Cubism Framework 能力建立可取消的逐帧更新循环，而不是重复绘制静态纹理。
- 每帧按正确顺序更新时间、活动 motion、表情层、眨眼/待机、Physics、Pose、模型和 renderer。
- 使用真实 delta time；页面隐藏、舞台离屏或适配器销毁时暂停并释放循环，恢复可见时继续。
- 不在每帧创建大数组、纹理或 WebGL buffer；单模型在 Founder 当前设备上应稳定流畅，无持续增长的内存或 GPU 占用。

### 3.3 状态与反馈

- `listen`：循环使用模型自己的 Idle motion；若模型没有 Idle，允许用标准参数做轻微呼吸、眨眼或视线变化。
- `confused / interest / drop`：优先使用模型已有 expression 或可解释的 motion 映射；Hiyori 开发样例必须至少对三种状态产生肉眼可区分的反应。
- 评价状态只能由 `CreatorAudienceStage.applyEvent()` 的现有判断事件触发，不能随机切换评价。
- 随机性只允许用于不表达评价的自然待机细节，例如眨眼间隔；不得让待机动作看起来像兴趣升降。
- 正式反应遵循当前约 1.6 秒停留策略，且可被新事件打断；结束后平滑回到 `listen`。
- B 模式保持静音。不要把 LipSync 做成角色正在说话的假象；本单不接 TTS。

### 3.4 无障碍与失败降级

- 尊重 `prefers-reduced-motion`：减少大幅位移和循环动作，但保留清楚的状态反馈，可使用较短表情变化、标签或轻微淡变。
- WebGL context 丢失、资源缺失、解析失败或逐帧运行异常时，停止循环、清理资源、显示具体原因，并回退到 bloub。
- 不留下空白 canvas、双重角色、后台计时器或重复 RAF。

## 四、测试要求

现有“canvas 存在 / 有像素”测试必须保留，但不得再作为 Live2D 动态完成的唯一证据。至少新增：

1. **时间推进测试**：推进两个以上动画时间点，证明 motion 或标准待机参数发生变化，并触发新的模型更新/绘制。
2. **事件反馈测试**：`confused / interest / drop` 分别进入可区分的反应状态，并在约定时间后回到 `listen`。
3. **可打断测试**：新事件可以覆盖尚未结束的旧反应，不等待旧动画播完。
4. **生命周期测试**：隐藏、恢复、销毁和重新挂载不会留下重复 RAF、计时器或 WebGL 资源。
5. **能力降级测试**：缺 motion、缺 physics、缺 expression、WebGL 丢失时均有确定行为，最终可安全回到 bloub。
6. **减少动态测试**：开启 reduced motion 后仍有状态反馈，但没有大幅循环动作。
7. 完成后运行 `npm run check`、`npm test`、Live2D 本机冒烟和 `git diff --check`。

特别注意：当前 `npm test` 会因 `docs/research/2026-09-10-v2-remediation-open-source-review.md` 不在 `main` 而中断。该文档在 `research/v2-market-position` 分支。不要顺手合并研究分支；请在交付报告中把它列为独立基线问题，并对本单新增测试给出单独通过证据。

## 五、Founder 人工验收

执行岗必须交付一个本地可见窗口，默认使用 Hiyori 样例；Founder 按顺序检查：

- [ ] **待机不是贴图**：静置 10 秒，能看到自然的眨眼、呼吸、视线或模型自带 Idle motion；动作克制，不像屏保。失败时提交 10 秒录屏。
- [ ] **训练事件有反馈**：分别触发“没跟上、兴趣回升、注意力下降”，三者肉眼可区分且与页面标签一致。失败时提交事件文字与角色同屏录屏。
- [ ] **能回到在听**：反应约 1.6 秒后回到待机；连续触发时新反馈立即接管，不叠加抽搐。失败时提交连续触发录屏和时间点。
- [ ] **静音不打断**：整个过程不发声、不追问、不抢麦克风，动作不改变兴趣分数。失败时记录声音或分数变化发生时刻。
- [ ] **降级可信**：人为移走一个非必要开发资源或模拟 context loss 后，界面给出具体原因并回到 bloub，无白屏和双重角色。失败时提交截图与错误日志。
- [ ] **减少动态可用**：系统开启减少动态后，大幅循环动作停止或显著减弱，但状态仍可识别。失败时提交前后对比录屏。

任何一项失败，本单不通过；“出现人物像素”不再等同于 Live2D 验收通过。
